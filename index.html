How a verdict is made

Measured, not improvised.

Every verdict comes from the Python engine. The browser never invents one, and neither does the server.

01 — Data

Two years of daily bars

The engine is fed a full analysis window whatever range the chart is showing, because momentum and volatility regimes need the history to be calibrated at all.

02 — Scoring

Factors, then a score

Indicators, patterns and valuation models each contribute to a scorer. The output is a recommendation with a confidence number you can argue with.

03 — Decay

Confidence that ages

A position's confidence is re-scored against price moves, recommendation drift, time since entry and stop-loss proximity. Entry-day conviction does not stand forever.

0

Fabricated verdicts. If the engine is unreachable, the app says so instead of showing a HOLD at 50% confidence.

4

Valuation models per fundamental verdict, so no single model's assumptions decide the outcome alone.

Engineering

The request path is the product.

A market page that polls is only as good as its slowest fetch, so the data layer is built around the cost of each upstream call.

Batched quotes

A 40-symbol dashboard costs one upstream call, not forty. Sparklines add a second multi-symbol call.

Per-symbol caching

Pages that share symbols fetch only what is genuinely missing, so moving between them is close to free.

Stale-while-revalidate

An expiring quote is served immediately and refreshed behind the response, so a poll never blocks on the upstream.

Market-aware cadence

Seconds while an exchange is open, minutes once every venue has closed. The client polls to match.
